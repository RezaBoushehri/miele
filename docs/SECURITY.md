# قفل نرم‌افزار و مقاوم‌سازی (License & hardening)

این سند توضیح می‌دهد قفل فلش چطور کار می‌کند، چطور آن را راه‌اندازی کنید، و تا کجا
می‌توان جلوی کرک را گرفت.

## صداقت درباره‌ی «غیرقابل کرک بودن»

هیچ برنامه‌ای که روی کامپیوتر شخص دیگری اجرا شود کاملاً غیرقابل کرک نیست — چون کد نهایتاً
روی سخت‌افزاری که در کنترل شما نیست اجرا می‌شود. کاری که می‌توان کرد **بالا بردن هزینه و
سختی کرک** است تا برای کسی که دنبال کپی غیرمجاز است صرف نکند. تدابیر این پروژه:

- کامپایل به کد ماشین native با Go (نه زبان مفسری/قابل decompile ساده مثل پایتون یا دات‌نت).
- حذف جدول نمادها و اطلاعات دیباگ (`-s -w -trimpath`).
- گره‌خوردن اجرا به **شماره‌سریال سخت‌افزاری فلش** و یک **امضای دیجیتال Ed25519** که فقط با
  کلید خصوصیِ شما ساخته می‌شود؛ کلید خصوصی هرگز داخل برنامه نیست.
- امکان ساخت نسخه‌ی **درهم‌سازی‌شده (obfuscated)** با `garble` که نام توابع/رشته‌ها را مبهم می‌کند.

این‌ها جلوی کپی ساده و دستکاری فایل مجوز را می‌گیرند. یک مهندس معکوسِ مصمم همچنان می‌تواند
با patch کردن باینری قفل را دور بزند؛ این محدودیت ذاتی هر نرم‌افزار آفلاین است. اگر امنیت
بالاتری لازم شد، گزینه‌ها: دانگل سخت‌افزاری تجاری (مثل HASP/Sentinel)، یا فعال‌سازی آنلاین.

## قفل چطور کار می‌کند

1. شما (صاحب نرم‌افزار) یک‌بار یک جفت کلید Ed25519 می‌سازید. کلید عمومی داخل برنامه جاسازی
   می‌شود؛ کلید خصوصی (`private.key`) فقط پیش شما می‌ماند.
2. برای هر مشتری، فلش را به کامپیوتر خودتان می‌زنید و با `keygen` یک **فایل مجوز امضاشده**
   (`miele.lic`) می‌سازید که روی همان فلش نوشته می‌شود. این فایل شامل شماره‌سریال سخت‌افزاری
   آن فلش، نام مشتری و تاریخ انقضا (اختیاری) است و با کلید خصوصی امضا شده.
3. برنامه هنگام اجرا، فلش‌های متصل را می‌گردد، `miele.lic` را می‌خواند، امضا را با کلید
   عمومی بررسی می‌کند و مطمئن می‌شود شماره‌سریال داخل مجوز با سریال واقعی همان فلش یکی است.
   اگر همه‌چیز درست بود اجرا می‌شود؛ وگرنه پیام خطا می‌دهد و بسته می‌شود.

کپی‌کردن `miele.lic` روی فلش دیگر بی‌فایده است، چون سریال سخت‌افزاری آن فلش فرق دارد و امضا
نمی‌خواند.

## راه‌اندازی (یک‌بار)

```bat
keygen.exe init
```
این کار `private.key` را می‌سازد (محرمانه نگه دارید، هرگز commit/ارسال نکنید) و کلید عمومی را
در `internal/license/pubkey.go` قرار می‌دهد. سپس **دوباره برنامه را build کنید** تا کلید
عمومی داخل `miele.exe` جاسازی شود.

> تا وقتی `keygen init` را اجرا نکرده‌اید، برنامه «provision نشده» است و اجرا نمی‌شود. این
> عمداً این‌طور است تا هیچ نسخه‌ای بدون کلیدِ شما قابل استفاده نباشد.

## ساخت مجوز برای هر فلش

فلش را بزنید و:
```bat
keygen.exe list
keygen.exe issue -drive E: -name "نام مشتری" -days 365
```
`-days 0` یا نبودنش یعنی بدون انقضا. فایل `E:\miele.lic` ساخته می‌شود. فلش را به مشتری بدهید؛
`miele.exe` فقط وقتی آن فلش وصل باشد اجرا می‌شود.

## ساخت نسخه‌ی مقاوم‌تر

```bash
go install mvdan.cc/garble@latest
./build.sh garble        # یا build.ps1 -Garble روی ویندوز
```

## چرخاندن کلید

اگر `private.key` لو رفت: `keygen init -force` یک کلید نو می‌سازد، برنامه را دوباره build و
توزیع کنید و برای فلش‌ها مجوز تازه صادر کنید. مجوزهای قدیمی دیگر کار نمی‌کنند.
